# Shapes that measured zero

Companion to `stack-skill-baselines.md`. That file records WHICH artifacts were
removed. This one records the **shapes** they had, because the names are already
gated and the shapes are not.

`scripts/lib/plugin-checks.sh`'s `pc_removed_refs` blocks a document that routes a
reader to `typescript`, `vue2`, `react-best-practices` and the rest. It cannot
block an author proposing `python-best-practices` or `nosql-data-modeling` — those
names were never removed, so nothing trips. That gap is not hypothetical: the
2026-08-02 coverage review's own synthesis proposed both, and both were killed by
the baseline-redundancy refuter citing the table below. A list of shapes, read
before writing, would have pre-empted them without an eval run.

**Read this before proposing any new skill.** If a proposal matches a shape here,
the burden is not "argue it is different" — it is to name what a blind control
would MISS, specifically enough to seed a fixture, and then measure it.

---

## The shapes, and their measurements

### 1. Per-version idiom maps

*"Version N introduced X, which replaces the older Y; version N+1 added Z."*

| Instance | Seeded | Control | Treatment | Delta |
|---|---|---|---|---|
| `typescript-best-practices` | 5 | 5/5 + extras | 5/5 | **0** |
| `javascript-best-practices` | 7 | 7/7 + extras | 7/7 | **0** |

Both plugins removed whole. In both runs the blind control found defects the
treatment missed. Language and framework version features are the single
best-represented thing in training data; the model does not need a map of them.

**The narrow survivor:** a version fact whose standard remediation has
**INVERTED** — where the answer a model confidently gives is now wrong, not merely
incomplete. `plugins/react-native/skills/react-native-best-practices/references/expo.md`
is scoped to exactly that: from SDK 55, `newArchEnabled: false` is a silently
accepted no-op, so the 2024/2025 remedy still in the corpus is now a dead end. One
fact of that kind beats forty of the ordinary kind, and it belongs in a
`references/` file at zero metered tokens, never in a description.

### 2. Canonical-doctrine checklists

*The most-recited advice in a domain, restated as a checklist.*

`react-best-practices` is the measured instance and it is the most damning result
in this repository: the treatment returned 5 findings, **every one a subset of what
the blind control found**, while the control additionally caught a real logic bug
(an order object overwriting user-details state), a missing fetch abort, and an
undefined-prop crash. The checklist did not add; it **narrowed**.

Recognising the shape: if the proposal's own summary reads like the first slide of
every conference talk in the domain — "enumerate access patterns before the key
schema", "measure before optimising", "assert behaviour not implementation" — it is
this shape. The 2026-08-02 review's proposed `nosql-data-modeling` skill was killed
on exactly that, and its author had already conceded in writing that the delta was
"a falsifiable prediction, not a measurement".

### 3. Style-rule catalogues

`bootstrap-`, `css3-`, `flexbox-`, `css-grid-best-practices`: 0, ≤0, 0, mixed.
The css-grid run scored **+1 / −2** — the treatment caught a grid-vs-flex routing
point and MISSED two real bugs the control found (98% arithmetic, a magic offset).

Formatting, naming and layout rules are the least drift-prone knowledge there is.
A style rule that matters is enforced by a formatter, and the useful artifact is a
pointer to the project's own config — which is why `code-review/hooks/conventions.sh`
emits config PATHS and deliberately not a digest of their contents.

### 4. Framework restatement

A skill whose body could be regenerated by reading the framework's own docs, with
no house decision, no lockfile-reading behaviour and no mechanism. Not separately
measured, but it is the common factor across all three shapes above and the reason
they scored zero: **restating public documentation is what a model already does.**

## What has NOT measured zero

Stated because a list of failures with no counterpart reads as "never write
anything", which is not the lesson:

- **A mechanism.** A script with an exit code, a hook that fires unasked, a gate.
  Nothing in the table above carried one.
- **A decision procedure with an ordering constraint** — freeze the target set
  BEFORE editing, read the CI config to learn which linter is authoritative,
  establish the distribution mode BEFORE judging a licence. The order is the
  content, and prose is the only place it can live.
- **Manifest- and lockfile-reading behaviour.** Not what a version does — where the
  truth about it lives when two local files disagree. See
  `plugins/stack-scan/skills/installed-versions/references/ecosystems.md`.
  `stack-skill-baselines.md:50-53` admits this was never actually exercised, which
  makes it the strongest untested claim in the marketplace, not a proven one.
- **Installation-specific knowledge.** Which agents exist here, which command
  applies a fix list, which routing row is dead. A blind model has no route to any
  of it.
- **Inverted advice.** Shape 1's narrow survivor, above.

## Standing

**Recorded.** No script reads this file. It is cited from
`claude-authoring/skills/authoring-skills` and from `/claude-authoring:new-skill`
so it is read at the moment a skill is proposed, which is the only moment it can
change anything. Making it a gate would mean pattern-matching prose against four
fuzzy shapes and failing the build on a judgment call — the false-positive class
that gets a gate switched off. The gate that DOES exist is
`pc_removed_refs` on the names; this is the argument the names were removed for.
