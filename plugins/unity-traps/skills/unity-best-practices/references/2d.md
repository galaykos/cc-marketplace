# 2D: URP 2D Renderer, pixel art, sprite atlases, 2D lights — Unity 6

> Last verified: 2026-10-30 — https://docs.unity.com/en-us/engine/6000.3/manual/unity2d/2d-urp/2d-pixelperfect

Read `com.unity.render-pipelines.universal` in `Packages/packages-lock.json` first, and check
which renderer the URP asset uses: a Renderer 2D asset means the 2D Renderer. Everything in
this file was re-read on the stamp date against the 6000.3 manual, the URP 17.3 API, the
Cinemachine 3.1 manual and the 2D Pixel Perfect 5.1 manual. Items marked "(URP source)" are
stated only in Unity's Graphics repository (`Packages/com.unity.render-pipelines.universal`,
master branch), not in the manual.

## Pixel Perfect Camera: URP ships its own

- In URP, use the Pixel Perfect Camera that URP ships
  (`UnityEngine.Rendering.Universal.PixelPerfectCamera`; the Universal 2D template already has
  it). Never install `com.unity.2d.pixel-perfect`: the 6.3 manual says it works only with the
  Built-in Render Pipeline, and its own docs say it is not compatible with SRP. If a URP
  project's `Packages/manifest.json` lists it, remove it and give each camera URP's component.
- Older code sets the booleans `upscaleRT`, `pixelSnapping`, `cropFrameX` and `cropFrameY`.
  They are obsolete since 2021.2 (URP source). Write `gridSnapping` and `cropFrame`.
- The component writes `Camera.orthographicSize` before every render (URP source), so a zoom
  that sets `orthographicSize` is undone in the same frame. Zoom through `assetsPPU` or
  `refResolutionX`/`refResolutionY`, and read the applied size from `ppc.orthographicSize`.
- Set Assets Pixels Per Unit to the PPU that every sprite in the scene uses.

## Settings that blur, shimmer or smooth pixels

- Filter Mode only acts when Crop Frame is Stretch Fill. Its default, Retro AA, stretches with
  bilinear filtering, which gives less shimmer and blurrier pixels. Point stays sharp and
  shimmers. With Crop Frame set to None, Pillarbox, Letterbox or Windowbox, Filter Mode does not
  apply.
- Grid Snapping defaults to None, which renders at full viewport resolution, so rotated sprites
  draw smooth diagonals. Upscale Render Texture renders at the Reference Resolution (larger on
  a wider or taller aspect) and then upscales. Pixels stay upright and square, and everything in
  the frame is pixelated with them. Pixel Snapping aligns sprite rendering to the grid and does
  not move the Transform.
- Snapping only changes rendering, so gameplay code still reads the unsnapped position. To put
  a spawned prop or a parallax layer on the art grid, use `ppc.RoundToPixel(position)` (URP
  source).

## Sprite import for pixel art

- The manual's setup: the same Pixels Per Unit on every sprite, Filter Mode Point, Compression
  None, and in the Sprite Editor each sprite's Pivot set to Custom with Pivot Unit Mode Pixels.
  The pivot step is the one usually skipped: a centre pivot on a 15-pixel sprite sits at 7.5.
- When the source is larger than Max Size, the import is downscaled with the Resize Algorithm
  (Mitchell by default), and a big sheet loses pixels without any warning. Set Max Size at or
  above the sheet's largest side.
- A platform override tab (Android, iOS, Web) replaces the Default tab. Compression None on
  Default therefore does not stop an enabled override from compressing the sprite.

## Sprite Atlas V2

- Once a sprite is packed, it renders from the atlas texture in the Scene view, the Game view and
  Play mode. The atlas has its own Filter Mode, Generate Mip Maps and Compression, plus platform
  tabs. For pixel art, set Point and None on the atlas as well. The sprites' own import settings
  do not make the atlas sharp.
- Under Project Settings → Editor → Sprite Atlas Mode "Sprite Atlas V2 - Enabled for Builds",
  the views show the unpacked sources. Atlases are built only for Play mode and builds, so a blur
  that only the atlas causes first shows up there.
- Turn Include in Build off and the Scene and Game views keep working, but in Play mode and in
  builds the sprites disappear. They come back only when a `SpriteAtlasManager.atlasRequested`
  handler loads the atlas (Resources or an AssetBundle) and passes it to the callback.
- A sprite packed into two atlases renders, at runtime, from whichever one Unity picks at
  random. Pack each sprite once, or late-bind.
- Turn Allow Rotation off when the atlas packs Canvas UI sprites, or the UI elements rotate.
  Give every sprite in one atlas the same set of secondary textures, or the combined normal and
  mask textures fill with empty space.

## 2D lights (URP 2D Renderer)

- 2D lights need a Renderer 2D asset assigned to the URP asset or to the camera. Without one,
  the Light 2D inspector warns "2D renderer data must be assigned to your universal render
  pipeline asset or camera" (URP source).
- Built-in 2D materials do not react to 2D lights. Sprites need `Sprite-Lit-Default` or a Sprite
  Lit Shader Graph, and `Sprite-Unlit-Default` ignores lights. The Renderer 2D asset's Default
  Material Type decides what new sprites get.
- `Light2D.normalMapQuality` and `normalMapDistance` are get-only in the URP 17.3 API. A Light 2D
  added from code starts with Normal Map Quality Disabled and Shadows on (field defaults, URP
  source). Enable normals in the Inspector or on a prefab. In editor code, write the serialized
  `m_NormalMapQuality` through `SerializedObject`.
- A normal map does nothing until the light's Normal Map Quality is Fast or Accurate. A mask map
  does nothing until the light's Blend Style is one of the "with Mask" styles. Attach both to the
  sprite as Secondary Textures named `_NormalMap` and `_MaskTex` in the Sprite Editor, not to a
  material. Import the normal map as Texture Type Normal map with sRGB off. Each light batch
  with normal maps adds a full-size depth pre-pass.
- Use one Global light per blend style and sorting layer, no more.
- Sorting layers share one light texture (a light batch) only when they need exactly the same
  lights and shadow casters. A light whose Target Sorting Layers skip one layer splits the batch
  and costs another light texture. Window → 2D → Light Batching Debugger names the light. Each
  distinct Blend Style also adds a light render texture, and the manual advises one or two per
  scene.
- Parametric lights are deprecated. The inspector asks you to upgrade them to Freeform (URP
  source).

## Tilemap Renderer and 2D sorting

- Tilemap Renderer Mode Chunk is not compatible with the SRP Batcher. The URP 2D lighting page
  tells you to set tilemaps to Individual or SRP Batch.
- Chunk also draws tiles in batches that other objects cannot sort between, so characters
  cannot appear between tiles at different depths. A Y-sorted top-down or isometric scene needs
  Individual, which costs performance because each tile sprite is drawn on its own.
- Detect Chunk Culling Bounds set to Auto can cull large tile sprites at the screen edge. Set it
  to Manual and extend Chunk Culling Bounds.
- With the 2D Renderer, Transparency Sort Mode and Transparency Sort Axis live on the Renderer
  2D asset. Project Settings → Graphics holds them only for the Built-in Render Pipeline.
  Top-down: Custom Axis (0, 1, 0). Isometric: (1, 1, 0).

## Cinemachine 3 with the Pixel Perfect Camera

- Add the `CinemachinePixelPerfect` extension (Add Extension in the CinemachineCamera inspector)
  to every CinemachineCamera. Without it, Cinemachine and the Pixel Perfect Camera both write the
  orthographic size and fight over it.
- Limits from the Cinemachine 3.1 manual: frames during a Brain blend are not pixel-perfect.
  Upscale Render Texture leaves fewer pixel-perfect sizes, so framing can be off by a large
  margin.
- Older URP tutorials add URP's own `CinemachineUniversalPixelPerfect`. It is deprecated and
  only logs an error in `OnEnable` (URP source). Use Cinemachine's extension.

## 2D physics in Unity 6

- The 6000.3 `Rigidbody2D` API lists `linearVelocity` (`linearVelocityX`/`linearVelocityY`),
  `linearDamping`, `angularDamping` and `bodyType`. Its `velocity`, `drag`, `angularDrag` and
  `isKinematic` pages are gone. Write the new names. The 3D renames are in `physics.md`.
- By default, a kinematic body touching another kinematic body or a static one neither collides
  nor sends callbacks. `useFullKinematicContacts = true` sends the callbacks, with no collision
  response.
