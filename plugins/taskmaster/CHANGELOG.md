# Changelog — taskmaster

Consumer-facing changes only. Newest first. Started at 0.50.4; earlier versions have no entries rather than invented ones.

## 0.54.0 — 2026-11-06

- **A `<walk>` whose surface is a file fails the card lint.** `card-shape-lint.sh` adds `walk-surface`: a surface ending in a listed image, 3D, video or audio extension (png, jpg/jpeg, webp, gif, glb, gltf, blend, fbx, obj, usdz, stl, 3mf, mp4, webm, mov, wav, mp3) exits 2. The match is case-insensitive on the part before `?`/`#`. http(s) URLs and `.svg`/`.avif` pass. task-runner walks only routes, at UI group close, so a `<walk>` on a rendered PNG was never run. `references/card-shape.md` gains the gate row, plus an agent-graded row: a look check on a render goes in `<change>`, rendered to PNG and Read. Known false positive: a route serving a listed extension (`/icon.png`). Standing: gate. `scripts/__tests__/card-shape-lint.test.sh` has two blocking cases (red on 0.53.0) and three route and URL cases.
- **Generation and modelling cards get the `asset` agent tag.** `references/agent-tags.md` adds `asset` for a card whose own run calls Meshy, Higgsfield or Blender (CLI or MCP), or creates `.glb .gltf .blend .fbx .obj .usdz .stl` outputs. It wins over `api`; server code that calls such a tool at runtime keeps `api`/`backend`. A baseline run on 0.53.0 tagged Meshy cards `api`, which would route them to web workers (`routing.md` `api` row). Standing: gate for the vocabulary (`card-shape-lint.sh` `agent-vocabulary`, `scripts/validate.sh` map sync); the derivation is agent-graded.
- **Goal mode never auto-takes a paid call's cost confirmation.** `ultra/SKILL.md` § Goal mode: auto-take excludes cost asks, and the never-suppress list says a paid external call's cost confirmation (Meshy, Higgsfield credits) is ASKED, never auto-taken. Before this, a Goal run could auto-confirm a credit spend. Standing: agent-graded — no script sees a paid call.

## 0.53.0 — 2026-11-06

- **grill asks for a detail level on every run: Guided or Exact.** Guided cards fix the goal, rules, interfaces and criteria and leave the implementation to the worker; their `<change>` opens `Direction (implementation is yours within must-not):`. Exact cards prescribe file-level edits and values, as before. grill recommends Exact for money, auth, stored data, migrations and public contracts, and picks by that rule when no user is present. The spec header records `Detail: guided|exact`; `scripts/spec-ledger-lint.sh` blocks any other value (`bad-detail`) and warns when the line is missing (`no-detail`), which keeps older specs converting to exact cards. Pinned by 5 new cases in `scripts/__tests__/spec-ledger-lint.test.sh`.
- **grill walks the known bugs of what the task builds, and the spec adversary has a sixth lens for them.** A known-bug catalog in `agents/spec-adversary.md` lists the classic failures per kind (UI state change, form, list, search, dialog, routing, auth, money, dates, upload, network call, stored data, jobs, migrations, game loop). grill turns each one that can happen into a ledger row with a recommended default in round 1's Accept-all list, so it becomes a success criterion; the adversary reports any the spec leaves unsettled. Why: a live run on 2026-11-05 shipped a signup form where a double click on Sign up hit the Start over button that replaced it; the spec, its adversary and the worker all missed it, and only the code red-team caught it. Agent-graded: no lint checks the walk happened.

## 0.52.0 — 2026-11-05

- **A fifth card lint checks the card against the tree: `scripts/card-paths-lint.sh --card <file>`.** It exits 2 on an unreplaced template token (`__B__`, an all-caps `{{CARD_ID}}`), on a `mode="edit"` file that does not exist, and on a path the `<verify>` line runs that neither exists nor is created by this card or a sibling card. PHP magic constants (`__DIR__`), Blade/Vue `{{ $x }}`, URLs, flags, globs and absolute paths are not hits. task-cards runs it beside the other card lints, and `references/card-shape.md` lists it as a gate. Why: in the 2026-11-05 retro (issue 9) cards halted workers on missing files, a verify target that did not exist and `__B__` left in verify lines. Pinned by `scripts/__tests__/card-paths-lint.test.sh` (12 cases). It flagged none of the 40 role-tagged cards in this repository's own `taskmaster-docs`. Misses: a file the change needs but the card never lists, and a stale card number in prose.

## 0.51.0 — 2026-11-05

- **task-cards copies a brief's `Verify: range` line into the index.** When the brief `/taskmaster:task` was given (overseer writes one per milestone), or the spec header, carries it, `00-INDEX.md` gets the exact line beside any `Ultra:`/`Goal:` marker; task-runner and candor read it. Never added on taskmaster's own judgment. `skills/task-cards/references/index-markers.md`.

## 0.50.6 — 2026-10-28

- **A bare `goal` first token is now described as what it does: boost + hands-off, the same as `ultra-goal`.** The `ultra` skill's description and trigger list, and the preambles of `/taskmaster:task`, `/taskmaster:redteam`, `/taskmaster:brainstorm` and `/taskmaster:coverage`, said hands-off only; each command's next sentence already ran it as `ultra-goal`. The `ultra` description also reads in short, plain sentences, with the same tokens and markers.
- **The `experience-walkthrough`, `erd` and `coverage-check` skills' descriptions now read in short, plain sentences.** Same triggers; each keeps the words the model matches it on.
