# Changelog — taskmaster

Consumer-facing changes only. Newest first. Started at 0.50.4; earlier versions have no entries rather than invented ones.

## 0.59.0 — 2026-11-13

- **A pass is looked at in a real browser before you see it.** `scripts/preview-check.sh [--page PATH] [--widths 375,768,1280]` loads a page (default `current.html`) from the preview server, starting it when none runs, in a local headless Chromium-family browser at each width, and prints one escaped JSON object per line: findings, widths not reported, then a summary; exit 0 is clean, 1 findings, 3 to 6 not checked or not at every width. It reports a blank page, console errors and failed loads (E1); sideways scroll, boxes cut off at the viewport, clipped or overlapping text (by the 0.8 em glyph band, so the shell's own type ramp passes) and targets under 24 px (E2); serious and critical axe-core violations of WCAG A and AA (E3); lorem ipsum, TODO, "Item 3", three identical rows and empty tables or lists outside an empty state (E4); identical variants, or variants differing in text, markup and colours at once (E5, advisory); and, for `current.html`, how many pixels changed since the previous ledger pass and where (E6, advisory, never counted). A full-page PNG per width is kept in the docroot's `.checks/` folder, which is never served. Each width is emulated exactly over the browser's DevTools pipe, because Chrome's headless window will not go below 500 px; nothing from Node or Playwright is needed, and nothing leaves the machine during a check: every host but 127.0.0.1 fails to resolve, a dead proxy wins over the environment's, WebRTC sends no UDP and downloads are refused. A web font the page starts late holds the check 3 s at most, a page with more than 4000 elements is measured on its first 4000 (`capped`), a busy page's widths read not reported with everything collected still printed, and a TERM from a caller closes the browser and removes its profile. Standing: gate for each check on its own fixture and for a clean shell page (`scripts/__tests__/preview-check.test.sh`, 72 cases; the browser half prints SKIP without a browser); with the checks unwired, each of the 11 per-check fixtures was missed.
- **visual-decisions checks each pass before asking for the pick.** After writing a pass it runs `preview-check.sh`, fixes what the findings show, re-runs once, and names what is left unfixed in one line; with no browser or on a lower rung it says the pass is not checked. Standing: agent-graded; no eval measures whether the model acts on a finding.
- **The shell shows whether this file was checked.** A badge in the header reads "checked: N findings" or "not checked" from serve.py's new `GET /_checks?page=`; a result counts only while the page's bytes are the ones checked, and an open tab updates when a check finishes. With `?static=1` its version picker stays hidden, so two passes screenshot alike. The check runs in an isolated world of the page that the script drives over DevTools, which also writes the records: no route serves the check or takes findings, so a script on a page (the one checked, or any open tab) cannot plant "checked: 0 findings" or hide what was found, and any page in the docroot can be checked, shell or not. A page key with a control character is no page (`/_checks` answers 404, not a dropped connection), and the folders of deleted pages go at the next run. Standing: gate for the routes and the event; the badge was driven once in Chrome (recorded).
- **axe-core 4.14.0 ships in `vendor/axe-core/`** (MPL-2.0, `axe.min.js` unmodified, 652 KB, with its licence and third-party notices); the harness pins its SHA-256.
- `preview-feedback.sh` exits 1 naming `find-browser.sh` when it cannot load it, instead of reading as "no browser"; its `shot` lays a viewport under 500 px out 500 wide (stated in its Misses).
- Misses: page script still runs while it is measured and can change what is measured (hide a defect, keep the browser busy, reach loopback services such as `POST /_feedback`), so a clean check is not proof; E2 overlap ignores absolutely positioned and inline text; E3 shows only what axe can decide from the DOM in the default state; E5's thresholds are a choice, not a measurement of what users notice; E6 compares pixels at one width, and a page that changed height reads as changed everywhere below the shift.

## 0.58.0 — 2026-11-12

- **Pick and comment in the browser; the model reads it without a chat message.** On serve.py, a page built from the shell now shows Pick and Note on each variant, a "Point & note" toggle (Alt+Shift+P; arrow keys and Enter also pick) that outlines the element under the pointer and opens a note box beside it, and a Notes list with each note's status and reply. Each click posts to the new `POST /_feedback`, which appends one clamped row to the docroot's `.feedback.jsonl`: the variant, the note, the element's CSS selector, tag, text and box, and the viewport, theme, width and state toggles in effect plus the last five console errors. The route takes Restore's guards (loopback peer even with a LAN key, local Host and Origin, an `X-Preview-Feedback` header, 1 to 8192 bytes of JSON; else 403, 413 or 400), and the file is a dot file, so it is never served. On a lower rung, over `file://` or with `?static=1` none of the controls appear. Standing: gate for the route (`scripts/__tests__/serve.test.sh`; 33 new cases, red on 0.57.0); recorded for the controls, driven once in Playwright Chromium on 2026-11-13, where it also found and fixed a keyboard pick that a resting pointer cancelled.
- **`scripts/preview-feedback.sh` reads the rows.** `list [--all]` prints unread open rows, `wait` blocks until one exists, prints it and marks it handed out (exit 3 after 600 s), `reply --id ID --status addressed|dismissed --text LINE` sets a row's status and one-line reply, which the page shows after a reload, and `shot --id ID` saves a PNG of the noted element outlined, using a local Chromium-family browser (exit 4 without one; `PREVIEW_BROWSER` points at one). Rows print as JSON lines with control and invisible characters escaped. A rewrite goes through a temp file and a rename under the lock serve.py takes for each append, so a note posted meanwhile is kept: unlocked, a harness race lost 16 to 17 of 60 posts in 3 of 3 runs. Standing: gate; `scripts/__tests__/preview-feedback.test.sh`, 43 cases.
- **visual-decisions asks for the pick through the page first.** After presenting, the skill starts `preview-feedback.sh wait` in the background. A pick row is confirmed in one line and taken as the answer; note rows are read as the user's comments on that variant, and each handled note gets a `reply`. With no row (timeout, or a lower rung) it asks through `AskUserQuestion` as before. Standing: agent-graded; no eval measures whether the model acts on a row.
- **Review fixes before release.** `wait` marked rows handed out before printing them, so a waiter killed or abandoned in between swallowed them; it now prints first, stamps `handed_out` with the time, and a row handed out more than 15 minutes ago that is still open is unread again. `wait` re-reads the file only when its size or modification time moves. Rows now also escape variation selectors, the Hangul fillers and the blank Braille cell, which render as nothing. `shot` loads the page over `http://127.0.0.1:<port>/` while `preview.sh`'s server answers instead of from `file://`, where page script had file-scheme reach; it runs Chrome with its sandbox on (off only as root or with `PREVIEW_BROWSER_NO_SANDBOX=1`) for at most 30 s, reports a browser that fails (exit 1), and prints "no browser" on stderr, not where `png=$(shot)` would take it for a path. The server stores a lone surrogate as `?` instead of dropping the connection, clamps numbers to ±10,000,000, keeps no text or element on a pick, and answers 507 once `.feedback.jsonl` would pass 2 MiB. In the shell, a data attribute holding a newline no longer breaks the picker, a console object with no `toString` no longer throws into the page, text is cut by code point, and `?static=1` also turns the reload client off. Standing: gate for the scripts and the route (`preview-feedback.test.sh`, `serve.test.sh`, each new case red first); recorded for the shell, run in Playwright Chromium before and after.
- Misses: any script on a served page, third-party script included, can post a pick or a note, and note text is unverified; the screenshot uses the default theme and states, not the row's; console errors thrown before the shell's script runs are missed; `python3 -m http.server`, a lower rung, serves `.feedback.jsonl` when one exists.

## 0.57.0 — 2026-11-12

- **The preview server no longer serves private files.** A dot-prefixed file or folder at any depth (`.env`, `.git/`, the server's own `.preview.*` files) and directory listings now answer 404, and dot files no longer appear on the session map, in the version picker or in reload events. Before, `serve.py` served all three, and Restore could copy a dot-named page over `current.html`. What an installer loses: a page or asset kept under a dot name is no longer reachable, and a folder without `index.html` no longer lists its files. Misses: a symlink inside the docroot is still followed out of it. Standing: gate; `scripts/__tests__/serve.test.sh`, the first harness for this server (35 cases passed on 0.56.1; 29 dot and listing cases failed there).
- **A launcher replaces background Bash and `lsof | xargs kill`.** `scripts/preview.sh` starts `serve.py` only when this docroot's server is not running and prints the URL either way, so the skills run it before every pass; `--stop` kills the recorded pid only after checking it is `serve.py` on that docroot. The old instruction killed whatever held the port. visual-decisions, erd and experience-walkthrough now call it; the fallback rungs (`http.server`, `php -S`, `npx serve`) are unchanged. What an installer loses: a server started by hand without the launcher now gets exit 4 (port busy) instead of being reused. Standing: gate for the launcher (`scripts/__tests__/preview.test.sh`); that the model calls it is recorded only.
- **LAN mode needs a key and ends on its own.** `--lan` prints a URL carrying a random key; a device on the network without it gets 403, and after the first visit a cookie carries it. The key is kept in `.preview.key` (mode 0600), so a restart keeps the URL. Restore now works only from this machine: before, under `--lan`, a device on the network could restore with the header alone. A LAN server exits after `PREVIEW_LAN_MINUTES` (default 60; 0 = no limit). What an installer loses: a phone holding an old LAN URL without the key is refused. Misses: plain HTTP, so the key is readable on the network; the cookie reaches any other server on the same address. Standing: gate; the remote-peer cases use the machine's own network address and skip without one, and the peer rule is also unit-tested.
- **Every preview server stops after 4 idle hours.** No completed request and no open event stream for `PREVIEW_IDLE_MINUTES` (default 240; 0 = off) ends it; an open tab keeps it up. Standing: gate (`serve.test.sh`, limits of seconds).
- **Review fixes before release.** Two starts at once could kill the healthy server, delete its pid file, or print `already running —` with no URL; the launcher now takes `.preview.lock` around check-and-start (a lock whose owner is dead is taken over), a losing start no longer truncates the winner's log, and a failed start removes the pid file only when it still holds its own pid. A machine without a usable `ps` read the live server as stale and deleted its pid file; the launcher now falls back to `/proc`, and a live pid neither can name is exit 6, signalling nothing and keeping the state. In LAN mode the launcher also prints `On this machine: http://127.0.0.1:<port>/`: Restore refuses a page opened from the network URL, even on this machine. A key file that is not UTF-8 crashed `--lan`, and a symlink there was followed for the read, the `chmod` and the write; both are now replaced. A request refused for want of the key no longer keeps an idle server up. Restore copies to a dot temp file and renames it over `current.html`, so a kill mid-copy no longer leaves it truncated (a `.restore-*.tmp` can be left instead). Standing: gate — `serve.test.sh` and `preview.test.sh`, each case red before its fix; the mid-copy kill itself is not reproduced, only the rename (a new inode).
- **A shell page says when the server stops and recovers by itself.** When serve.py's event stream drops, a status bar reads "Preview server stopped"; the page retries with backoff (1 s doubling to 10 s) and reloads once the server answers. Before, the page fell back to polling for good. Lower rungs poll as before and never show the bar. Not measured: driven once in Chromium on 2026-11-12 (stop, bar, restart, reload, then a push reload); no harness runs a browser, so standing is recorded. `assets/preview-toolbar.html` has no reload client and is unchanged.

## 0.56.1 — 2026-11-12

- **A boosted run no longer adds clarify rounds or a second dry coverage round.** `ultra` told grill "extra clarifying rounds; no early ledger exit on first CLEAR sweep", against grill's own rule that a question must be able to change what gets built, and told coverage-check to stop "at two dry rounds or the 3-round cap", against coverage-check's "zero findings ends it". Both lines are gone; coverage-check's own loop decides. In the sessions the 2026-11-05 retro read, coverage rounds 2 and 3 found nothing. What a boosted run loses: the forced re-sweep of an all-CLEAR ledger and the second confirmation round.
- **Grill follows the approaches plugin's own choice of mechanism.** It ran the four-agent blind panel for every approach decision; `approaches:approach-deliberation` says the inline slate is the default and the panel is for rework of existing code. Grill now defers to that rule. `/taskmaster:brainstorm` is unchanged and still runs the panel. Standing: agent-graded; no script checks which mechanism ran.

## 0.56.0 — 2026-11-12

- **Each session has its own phase sentinel.** `scripts/phase-sentinel.sh` writes `<project root>/.claude/cc-phase/<session>.json`, one file per session, and `clear` removes only the caller's file. Before, one repo-wide `.claude/cc-phase.json` was shared: session B's write replaced session A's, B's clear removed it, and a sentinel written without `--session` silenced reminder hooks in every session. `write` and `clear` now require `--session` (exit 3 without it); `/taskmaster:task` and `/taskmaster:brainstorm` pass `${CLAUDE_SESSION_ID}`, which the host substitutes. The reminder hook reads only its own session's file, and so does the phase in its rank key (`cc_phase_now`). Another session's phase no longer moves which reminder speaks. The 120-minute TTL is kept: any reader deletes expired files in `.claude/cc-phase/`. The directory carries its own `.gitignore` (`*`). Standing: gate; `scripts/__tests__/phase-sentinel.test.sh` sections 10–11 (two sessions, legacy) and the marketplace repository's `scripts/smoke/hook-guard-tests.sh` rank-key case fail on 0.55.0.
- **`shape-guard.sh` reads this session's sentinel only.** B's brainstorm no longer guards A, and B's clear no longer lifts A's guard. An owner-less sentinel no longer applies to every session. Standing: gate; `scripts/__tests__/shape-guard.test.sh`.
- **Migration: the old `.claude/cc-phase.json` is ignored.** No reader honours it. A `write` or `clear` removes it when it names no session, names the caller, or is past the TTL; one owned by another live session is left to that session. Update taskmaster with the plugins that call its writer (code-architecture, git-workflow, task-runner). An older taskmaster accepts `--session` but still writes the repo-wide file, and its `clear` deletes that file whoever wrote it. task-runner 0.55.1 checks for the per-session file and writes it itself; `/work` and `/finish` tell the model to do the same.

## 0.55.0 — 2026-11-07

- **Brainstorm's no-code rule is enforced for Write and Edit.** `/taskmaster:brainstorm` now writes a `shape` phase sentinel (`scripts/phase-sentinel.sh`, owner `taskmaster:brainstorm`) and clears it when the user approves the design doc or the run is abandoned. The new PreToolUse hook `hooks/shape-guard.sh` denies Write/Edit/MultiEdit to any project file outside `taskmaster-docs/` and `.claude/` while that sentinel is live for the session. visual-decisions' `__design-preview__` scratch passes. Until now the command called the rule `unenforceable`. Residual: writes through Bash or NotebookEdit are not seen, and `/taskmaster:task`'s own shape phase is not guarded. Standing: gate (Write/Edit/MultiEdit); `scripts/__tests__/shape-guard.test.sh`, 18 cases.
- **`card-set-lint.sh` checks ordering across a card set.** `--dir <cards>` exits 2 when a card reads an `<interface>` another card produces without depending on it (directly or through others), when it edits or verifies a file a sibling creates without depending on it, or when a `<depends-on>` is missing, self-referencing, cyclic or not a number. task-runner schedules by `<depends-on>`, so such a card could run first. A path already on disk is skipped for the create check, because a follow-up card is added after its producer ran. task-cards runs it once after the per-card lints. Standing: gate; `scripts/__tests__/card-set-lint.test.sh`, 12 cases.
- **Coverage re-checks stay small.** After resolutions, coverage-check re-checks only the cards and criteria they edited, inline, and the first round with zero findings ends the loop. In three recorded overseer runs, full re-dispatches after round 1 found nothing new. Standing: agent-graded.

## 0.54.0 — 2026-11-06

- **A `<walk>` whose surface is a file fails the card lint.** `card-shape-lint.sh` adds `walk-surface`: a surface ending in a listed image, 3D, video or audio extension (png, jpg/jpeg, webp, gif, glb, gltf, blend, fbx, obj, usdz, stl, 3mf, mp4, webm, mov, wav, mp3) exits 2. The match is case-insensitive on the part before `?`/`#`. http(s) URLs and `.svg`/`.avif` pass. task-runner walks only routes, at UI group close, so a `<walk>` on a rendered PNG was never run. `references/card-shape.md` gains the gate row, plus an agent-graded row: a look check on a render goes in `<change>`, rendered to PNG and Read. Known false positive: a route serving a listed extension (`/icon.png`). Standing: gate. `scripts/__tests__/card-shape-lint.test.sh` has two blocking cases (red on 0.53.0) and three route and URL cases.
- **Generation and modelling cards get the `asset` agent tag.** `references/agent-tags.md` adds `asset` for a card whose own run calls Meshy, Higgsfield or Blender (CLI or MCP), or creates `.glb .gltf .blend .fbx .obj .usdz .stl` outputs. It wins over `api`; server code that calls such a tool at runtime keeps `api`/`backend`, and importing or testing an existing asset keeps its file-derived tag (a re-run first tagged a Godot import test `asset`; unmeasured since the fix, 1 run before it). A baseline run on 0.53.0 tagged Meshy cards `api`, which would route them to web workers (`routing.md` `api` row). Standing: gate for the vocabulary (`card-shape-lint.sh` `agent-vocabulary`, `scripts/validate.sh` map sync); the derivation is agent-graded.
- **Goal mode never auto-takes a paid call's cost confirmation.** `ultra/SKILL.md` § Goal mode: auto-take excludes cost asks, and the never-suppress list says a paid external call's cost confirmation (Meshy, Higgsfield credits) is ASKED, never auto-taken. Before this, a Goal run could auto-confirm a credit spend. Residual: a card with no cost ask bypasses it — in 1 post-change run headless grill pre-granted the spend as an ASSUMED default. Standing: agent-graded — no script sees a paid call.

## 0.53.0 — 2026-11-06

- **grill asks for a detail level on every run: Guided or Exact.** Guided cards fix the goal, rules, interfaces and criteria and leave the implementation to the worker; their `<change>` opens `Direction (implementation is yours within must-not):`. Exact cards prescribe file-level edits and values, as before. grill recommends Exact for money, auth, stored data, migrations and public contracts, and picks by that rule when no user is present. The spec header records `Detail: guided|exact`; `scripts/spec-ledger-lint.sh` blocks any other value (`bad-detail`) and warns when the line is missing (`no-detail`), which keeps older specs converting to exact cards. Pinned by 5 new cases in `scripts/__tests__/spec-ledger-lint.test.sh`.
- **grill walks the known bugs of what the task builds, and the spec adversary has a sixth lens for them.** A known-bug catalog in `agents/spec-adversary.md` lists the classic failures per kind (UI state change, form, list, search, dialog, routing, auth, money, dates, upload, network call, stored data, jobs, migrations, game loop). grill turns each one that can happen into a ledger row with a recommended default in round 1's Accept-all list, so it becomes a success criterion; the adversary reports any the spec leaves unsettled. Why: a live run on 2026-11-05 shipped a signup form where a double click on Sign up hit the Start over button that replaced it; the spec, its adversary and the worker all missed it, and only the code red-team caught it. Agent-graded: no lint checks the walk happened.

## 0.52.0 — 2026-11-05

- **A fifth card lint checks the card against the tree: `scripts/card-paths-lint.sh --card <file>`.** It exits 2 on an unreplaced template token (`__B__`, an all-caps `{{CARD_ID}}`), on a `mode="edit"` file that does not exist, and on a path the `<verify>` line runs that neither exists nor is created by this card or a sibling card. PHP magic constants (`__DIR__`), Blade/Vue `{{ $x }}`, URLs, flags, globs and absolute paths are not hits. task-cards runs it beside the other card lints, and `references/card-shape.md` lists it as a gate. Why: in the 2026-11-05 retro (issue 9) cards halted workers on missing files, a verify target that did not exist and `__B__` left in verify lines. Pinned by `scripts/__tests__/card-paths-lint.test.sh` (12 cases). It flagged none of the 40 role-tagged cards in this repository's own `taskmaster-docs`. Misses: a file the change needs but the card never lists, and a stale card number in prose.
