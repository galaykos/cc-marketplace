# Changelog — taskmaster

Consumer-facing changes only. Newest first. Started at 0.50.4; earlier versions have no entries rather than invented ones.

## 0.63.0 — 2026-11-16

- **Specs now settle the contracts between cards before any card exists.** A spec that becomes two or more cards carries `## Shared state & invariants` (one `I<n>` row per entity or flow: states and their exits, the one writer, the invariant a reviewer can check against a diff, what each error means) and `## Module map` (what each unit owns, where the next variant plugs in, and the existing code to extend). The plan check writes both from the scout report and the decisions; they are not new questions. The format is grill's `references/contracts.md`. Why: two real runs' reviews (62 findings) traced the largest share to cards that each assumed half of a contract (a status with no exit, two writers of one snapshot, a poll that queued a job on every tick) and to helpers rewritten beside a sibling that already had them.
- **`/taskmaster:task` always runs the plan check for a multi-card spec, before the red-team** (was: optional, after it, and only with code-architecture installed). It uses plan-before-code when installed and works inline otherwise. spec-adversary also attacks the invariants table: a state with no exit, two writers, a poll or GET that enqueues work, a lock taken in two orders.
- **context-scout reports a seventh section, Reuse candidates**: existing helpers, state lists, services, components and test factories the cards should extend, as `path:line symbol`. Ultra's two-lens split gives it to the surface lens.
- **Cards carry the contract.** New tags: `<reuse path= symbol=>` in `<facts>`, `<invariant id="I<n>">` in `<must>` holding the spec row's Invariant cell verbatim, and `kind=` on every `<interface>` (`payload event factory state route component signature`).
- **Lints.** `card-shape-lint.sh`: `interface-kind`, `reuse-shape`, `invariant-id` (gate). `card-paths-lint.sh`: `reuse-missing` (gate), `reuse-symbol` (WARN). `card-set-lint.sh`: `invariant-unknown` and `invariant-drift` against the spec named in `00-INDEX.md` or `--spec` (gate), `invariant-orphan` (WARN). `spec-ledger-lint.sh`: `invariants-shape` (gate), `no-invariants` (WARN).
- **Breaking for new cards:** an `<interface>` without `kind=` now fails `card-shape-lint.sh`. Card sets already linted are not re-linted.
- Standing: gate for the lints (`card-shape-lint.test.sh`, `card-paths-lint.test.sh`, `card-set-lint.test.sh` with a replay of the poll-and-dispatch pair, `spec-ledger-lint.test.sh`); agent-graded for whether a section is needed, complete and true; recorded for the command, skill and agent text.
- Misses: no lint knows that a card touches shared state but cites no `<invariant>`, or that a `<reuse>` names the wrong code; `reuse-symbol` greps the name after the last `::`, `->` or `.`, so it can pass on an unrelated match. Both table readers treat `\|` as a pipe inside a cell and match the section heading in any case.

## 0.62.0 — 2026-11-15

A mockup page was held to three layout variants in one neutral theme. It now holds more directions, and shows every one of them in several colour, style and type versions of your own content. Three words used below: a frame is one lettered option on a mockup page, a pass is one round of frames for a decision, and the look is the palette, style and type active on the page. If you have mockup pages or habits from the older shell, read the last part of this entry.

- **A layout choice shows 3 directions on one page by default, up to 5, and never more than 6.** The shell (`skills/visual-decisions/assets/shell.html`) ships six frame blocks, A to F, where it had three. On a layout pass (the frames are layout directions) or a creative pass (concept, copy, tone) visual-decisions shows 3 by default, up to 5 and never fewer than 2; a sixth frame appears only as one frame kept from the pass before plus five new ones. A decision takes up to 3 passes, and you ask for the next one in chat: "more like B" keeps that frame and adds up to 5 variations of it, "different directions" replaces every frame, and a mix of two gives the merged frame beside the two it came from. Every other pass kind (data shape, theme axis, motion) keeps at most 3 frames and two passes. The reason: the cap of three rested on one unsourced sentence about choice overload. The new numbers match what comparable tools ship and are a judgment, not a measured optimum; the sources are in the marketplace repository's `rationale/derivations/plugin-taskmaster.md`, under the heading `plugins/taskmaster/skills/visual-decisions/SKILL.md § count rule`. Standing: a seventh frame is a gate where the render check runs (check E7, below); the default of 3, the floor, the condition on a sixth frame and the pass rules are agent-graded.
- **A frame's letter is its position on the page.** The first frame is A whatever its `id`, and the jump links, the number keys 1 to 6, picks, notes and the render check's findings all use that letter. A number key now moves keyboard focus to its frame, and a frame reached by a key or a jump link lands below the sticky header. A frame's title buttons sit in one group, in the order Focus, Replay (where the frame has one), Pick, Note, each at least 24 px tall and wide. Standing: gate, in `scripts/__tests__/shell-controls.test.sh`. That harness is new: it drives the page in a headless Chromium with real clicks and key presses, and on a machine with no browser it prints SKIP and passes unless `PREVIEW_REQUIRE_BROWSER=1`.
- **Palette, Style and Type switchers restyle every frame at once.** On a layout or creative pass the header carries up to three switchers, in that order, with at most 4 named options each: Palette sets colours, Style sets corner radius, spacing and shadow, Type sets a system font stack. Choosing an option changes the content of every frame and nothing else on the page, so the frames keep differing on layout alone while you see each of them in every colour version. A switcher with fewer than two options is not shown, though a lone option is still applied. In a window 600 px wide or narrower the row folds behind a `Look` button, and under it a switcher's options wrap onto further lines, each at least 24 px tall, so a long name is neither cut off nor pushed out of the window. A browser tab keeps its palette, style, type, Scheme and Direction across reloads, and from one pass to the next while the page keeps its path and title. The author writes each option as one CSS rule in the shell's new `<style id="vd-presets">` block; `skills/visual-decisions/references/shell-authoring.md` gives the exact selectors, the tokens each kind may set and a map from a project's theme tokens to the shell's. Standing: gate (`shell-controls.test.sh`); the limits are check E7.
- **A header much taller than half the window no longer sticks.** The page's header stays at the top of the window while you scroll. Once it is taller than 55% of the window it now scrolls away with the page, so that it cannot cover the frame a number key or a jump link takes you to, and it sticks again once it is 45% of the window or less. There are two thresholds so that a phone's URL bar, which changes the window's height as it slides in and out, does not flip the header on every scroll; and the page follows a control in the header only when the header itself grew (`Look` opened), never because the window changed size. On a six-frame page in a window 375 px wide and 800 px tall the header measured 305 px closed, 38% of the window's height, and 394 to 427 px with `Look` open, 49 to 53%, so it stays stuck there; at 320 by 480 px it does not stick. Before, it stuck at any height. Standing: gate (`shell-controls.test.sh`, at 320 by 480 px with `Look` open and at each threshold to the pixel); no phone was used, the URL-bar case is driven as window heights (628 and 553 px), and the 375 px heights are measurements from two desktop browsers.
- **The project's own theme is the first Palette option, `Project`; the Theme toggle is gone.** A project with a theme gets `Project` first and `Neutral` second, and its font and its radius and spacing become a first option named `Project` in Type and in Style. Colours the project does not define keep the neutral values. A palette with no dark colours holds the page on the light scheme and disables the Scheme toggle while it is active, with the note `<Name> has no dark set` beside it; your own Scheme choice returns under a palette that has dark colours. Frames print in the active palette's light colours whatever the scheme. A project with no theme gets `Neutral` plus proposed palettes, and the header note says they are proposals. The reason: one toggle could show the project's theme or the baseline and no third colour version. Standing: gate for `Project` listed first, the absent toggle, the disabled Scheme toggle and print (`shell-controls.test.sh`); filling `Project` from the project's own values and writing the header note are agent-graded.
- **Colour on your own content is explored on the mockup page.** grill, `/taskmaster:task`, visual-decisions and its real-component reference sent a colour decision to `/ui-ux:theme`. They now send colour on your own content to the Palette switcher of a layout or creative pass. `/ui-ux:theme` itself is unchanged: it still decides and writes the theme, and stays the command for a colour decision with no mockup. Standing: recorded.
- **A pick records the frame, the pass and the look.** Pick on a frame stores its letter (A to F), the page's pass number as `pass` and the active palette, style and type as `switchers`; a note stores the same two fields. A row's `context.theme` now reads `<palette or baseline> <light or dark>`, and a new field, `context.scheme`, holds the scheme on its own: `light` or `dark`, and null when the page sends anything else or nothing. The picked frame's button reads `Picked with <palette>, <style>, <type>` (plain `Picked` on a page with no look), and `Pick with current look` once you change the look, which stores a new pick when pressed. A look change that makes the look stop matching the pick, or match it again, is also written to the page's status region for screen readers, in one sentence naming the frame. A frame reads as picked only while the newest pick carries the page's own pass number, so a new pass opens with nothing picked. A double click stores one row: a pick equal in letter, pass and look to the page's newest pick is dropped while the agent has not read that one. The server finds that newest pick by reading its feedback file from the end and parses no row before it. A first version of the comparison parsed the whole file on every pick: on a 2 MB file of 3655 rows a pick post took 10.39 ms that way and 0.49 ms this way, with the page's newest pick four rows from the end (the median of 21 posts on one machine, reported by the agent that made the change and not measured again). A page with no pick in the file gains nothing: 11.49 ms before, 11.57 ms after. The agent writes the letter and the look to the ledger, quotes both in the spec and saves the winning frame to the gallery so that it opens in the picked look. With no pick from the page it asks in chat, the frame first (for 5 or 6 frames, the first three letters plus "Another frame") and then one question for each switcher shown; on a hands-off run it takes a recommended frame and look and records the choice as assumed. A picked palette is the starting point for `/ui-ux:theme` when ui-ux is installed: the skill says so, nothing hands it over, and that command still decides. Standing: gate for the stored row, the dropped repeat, the button's texts and the sentence in the status region (`scripts/__tests__/serve.test.sh`, `shell-controls.test.sh`); the timings are recorded; what the agent does with a pick is agent-graded.
- **A refused pick or note says so beside its control.** A line appears under the frame's title buttons, or beside `Send note`. It reads `Not recorded: <the server's own sentence> (<status>)` when the server gives its reason (a full feedback file, 507, is one), `Not recorded: the server answered <status>` when it gives none (403 and 413), `Not recorded: no answer from the server in 10 s` when a post gets no answer in that time, and `Not recorded: the server did not answer` when the connection fails. The server's sentence is shown as plain text, cut at 200 characters. Before, only the page's screen-reader announcement carried a refusal, and a post the server never answered left its control as it was, with no message. Standing: gate (`shell-controls.test.sh`; the server's sentences come from a stand-in server that copies them, not from the real server's 507).
- **The render check reads every palette and every option, not only the look the page loads with.** `scripts/preview-check.sh` gains two checks and widens one. E7, on a layout or creative pass: more than 6 frames, more than 3 switchers, more than 4 options in a switcher, an option name used twice, or a name the server will not store (anything but 1 to 24 ASCII letters, digits, spaces, hyphens and underscores). E8, on any page with a palette: for each palette in light and, where it has dark colours, in dark, body, soft, button, chip, alert or nav text, or the primary colour used as text, under 4.5:1 against the colour behind it; the finding names the palette and the scheme. E2, the layout check, runs again at 375 px under each style option and each type option the page did not load with, and such a finding names its option. Each look checked this way is called a state: a palette in a scheme, or a style or type option at 375 px. A run checks at most 16 states, and they share 16 s on top of the run's 60 s limit. A state past the sixteenth, one that no longer fits in what is left of the 16 s, or one that does not finish in it, is not dropped in silence: it is named in a line of its own, `{"not_reported": <width>, "state": {"check": "E2", "type": "Mono"}, "reason": …}`, and the run exits 5. The summary line counts the states that ran as `"states"` and the rest as `"states_not_run"`. E7's switcher and option limits, and the list of states, are read from the page's header only, so a control that a frame draws as its own content with the switcher's attributes draws no finding and adds no state. One rule says a palette has no dark set, for E8 and for the page's Scheme toggle alike: its first rule sets a value and it has no dark rule. A dark rule counts at the top level of the presets block or directly inside an `@media screen` block; inside any other at-rule (`@media print`, `@supports`, a narrower `@media screen and (…)`) it is not read. A proposed palette that still fails E8 after one fix is removed from the page; the project's own is always shown, with a low-contrast note in the header. Standing: gate, each check on its own fixture (`scripts/__tests__/preview-check.test.sh`), the cap of 16 and the named states included; the harness lowers the 16 s to make states miss it and never waits it out, and no case holds the run's own limit; acting on a finding is agent-graded.
- **The launcher replaces a preview server started from an older `serve.py`.** `scripts/preview.sh` reused whatever server ran for the folder, and a server from before this version refuses a pick on frame D, E or F and drops the pass and the look from every row. The server now reports a version number, and the launcher compares it with its own `serve.py`: an equal one is reused, an older one (or one that gives no answer in 2 s) is stopped and started again on the same port with the same `--lan` setting, and a newer one is left running with a line saying its controls may be refused. An older server still running 3 s after its stop signal is exit 4, with its state files kept. Standing: gate (`scripts/__tests__/preview.test.sh`).
- **A note's screenshot shows the look the note was written under.** `preview-feedback.sh shot` renders the page in the row's palette, style, type and scheme, where the row holds the name and the page still has that option. The scheme is the row's `context.scheme`; for a row that has none, the last word of its `context.theme` is used. The picture now starts at the page's header and holds the outlined element: before, it could begin with a band of blank rows, and in a small window the element could fall outside it. Standing: gate (`scripts/__tests__/preview-feedback.test.sh`; the cases need a browser).
- **visual-decisions checks a pass as its dated file, then once more as `current.html`.** A check result belongs to the file it ran on. So the dated file is checked and fixed before it is copied over the live page, and the copy is checked once so that its header badge does not read "not checked". Standing: agent-graded.
- **`/taskmaster:brainstorm` stages a creative decision on a mockup page.** It said creative choices never go to the shell. A creative pass is a shell page whose frames may differ in concept, copy and tone: the count rule and the switchers apply, the layout-only rule does not. Describing each direction in words stays the fallback when you declined mockups. Standing: recorded.
- **Not built yet.** Buttons on the page that ask for another pass ("more like this", "different directions"): you ask in chat. Binding the picked look: it is recorded in the pick's row, the ledger and the spec, and nothing holds the implementation to it or writes it into a theme. Any change to `/ui-ux:theme` or to the ui-ux plugin.
- **Correction to the 0.59.0 entry below.** It says `preview-feedback.sh shot` "lays a viewport under 500 px out 500 wide". That was wrong. Script on the page reads a window 500 px wide while the page loads; the capture then resizes the window to the row's viewport, and the PNG is the page laid out at the width asked for, not a cut of a 500 px layout. The measurement is in the marketplace repository's `rationale/derivations/plugin-taskmaster.md`, under the heading `plugins/taskmaster/scripts/preview-feedback.sh`, section "Blank rows above the header in a shot". The 0.59.0 entry is left as it was written.
- Misses: a pick is told apart by its page file and pass number only, so a later decision written into the same file that reaches the same pass number opens with the earlier decision's frame marked `Picked`; nothing compares the pass number on `<body>` with the visible "pass 1 of 3" text; E7 holds a page only while its `<body>` is marked `layout` or `creative`, and nothing checks that layout frames differ on layout alone (E5 stays an advisory); E8 does not read text over a background image, text dimmed by opacity or text that is none of the shell's own parts; E2 under an option runs at 375 px only and never under a style together with a type, and a CSS transition on a layout property hides an option's overflow from it; a screenshot still uses the default states, direction and width preset, and a header taller than the window hides the noted element; a launcher restart closes the event streams of open tabs and starts the idle and LAN time limits again, a current server slower than 2 s is restarted as if it were older, and a tab left open across a restart was not tested; frames print in a palette's light colours only when the page's script has run; a tab keeps its look under the page's path and title, so a changed title starts from the page's own look; a pick or note the server stores after the page gave up waiting at 10 s has already been reported as `Not recorded` (measured for a pick; that a note sent again is then stored twice is inferred, not measured), and a 403 or 413 shows its status without the server's sentence; a state the render check did not run shows only in its output and its exit code: the record stored for that width does not carry it, and the header badge probably counts the width as checked; above 600 px the switchers do not wrap (a page with four 24-character names in each switcher measured 696 px wide in a 601 px window), and a name with no space or hyphen folds in the middle of a word; a window in which the header is taller than half its height has no sticky header at all; what a screen reader speaks on a look change was not tested, and nobody ran Firefox or Safari; the repeat-pick comparison still parses up to the whole file for a page whose newest pick lies far back in it or that has none; a page copied from an older shell posts no `context.scheme`, so its rows hold null there and a screenshot takes the scheme from the theme's last word.

### If you have mockup pages or habits from the older shell

A page already written is a self-contained copy of the shell it came from. It keeps its own frames and Theme toggle, and the server still stores its picks, with no pass number and no look. The points below are for the next page you write and for content you carry over.

- **The Theme toggle is gone, and so are `SLOT: theme-project` and the `data-vd-theme` attribute.** Write the project's theme as the palette option `Project`: the first rule in the shell's `<style id="vd-presets">` block, in place of `/* SLOT: palettes */`, as `html[data-vd-palette="Project"] .vd-content { … }`, followed by an empty rule for `Neutral`. Set only the colours the project defines. The project's font goes in a first Type option named `Project`, its radius and spacing in a first Style option named `Project`. One difference to expect: the old slot set its values for the whole page, header included, and a palette reaches frame content only.
- **Delete trailing frame blocks only.** The shell ships six blocks and a letter is a position, so for three frames delete the D, E and F blocks, from `<!-- FRAME-D-START -->` to `<!-- FRAME-F-END -->`. Deleting a block in the middle shifts every later letter: content written into the E slots would show, and be stored by a pick, as D.
- **Mark the pass on `<body>`.** The shell ships `data-vd-pass-kind="layout" data-vd-pass="1"`. A creative pass says `creative`. A page of any other pass kind (data shape, theme axis, motion) must remove `data-vd-pass-kind`, or it is treated as a layout pass: it draws the switcher row when options are authored and is checked against a layout pass's limits. Set `data-vd-pass` to the pass number, 1 to 9, on each new pass; the visible "pass 1 of 3" text is a separate input.
- **`preview.sh` no longer reuses every running server.** One started from an older `serve.py` is stopped and started again on the same port, which closes the event streams of open tabs.
- **A pass is checked twice.** Run `preview-check.sh --page <dated file>` before copying the file to `current.html`, then check `current.html` once after the copy: until its own check has run, the copy's header badge reads "not checked".
- **An older page keeps the older screenshot.** `preview-feedback.sh shot` on a page copied from the older shell ignores the row's look, and can still begin with blank rows above the header or leave the noted element out.
- Unchanged: the theme-axis pass, its per-frame presets in `SLOT: custom-css`, and `scripts/theme-axis-check.py`.

## 0.61.0 — 2026-11-14

- **`preview-cleanup.sh` no longer fails after every real-component pick.** It searched the whole project for the `__design-preview__` marker, and the ledger row that records the pick quotes the scratch path, so cleanup printed `artifacts REMAIN` and exited 1 from then on. File contents under `.cc-artifacts/` and `taskmaster-docs/` are no longer searched. `--verify` now works after the project root as well as before it (it ran the deleting mode there), and an unknown option exits 2.
- **A walkthrough's dated copy is no longer offered as a past mockup pass.** `serve.py` listed `YYYY-MM-DD-<slug>-walkthrough.html` in the version picker and Restore copied it over `current.html`. Files ending `-walkthrough.html` are left out of the list and refused by Restore. A mockup pass whose own topic ends in `-walkthrough` is left out with them.
- **The card-lint observer sees a skipped `card-paths-lint.sh`.** That lint has written a run record since it shipped, and the hook read only the other three. The warning now names all four.
- **spec-adversary no longer asks whether a card builds each visual decision.** It runs before any card exists, so the question had no answer. Coverage-check keeps that check.
- **Under a boost, card-verify is now defined: the builder check.** After the card lints, a fresh subagent reads each card with nothing else in hand, as the worker who will run it, and lists what it would still have to ask. Each question is fixed in the card before the handoff (`skills/ultra/references/dispatch-tiers.md`). Agent-graded and unmeasured.
- **A boosted goal run gets the red-team panel and scans the visual surface.** The panel was keyed to the `ultra-task` directive alone, and a two-lens recon skipped context-scout's Visual surface section. Both now hold under either boost directive.
- **A goal index always carries both markers, with literal values.** `Ultra: true (model=auto, effort=xhigh)` and `Goal: true (model=auto, effort=xhigh) — …`; the reference no longer asks for a "resolved" tier, and the hook directive names both lines.
- **The ultra skill says what the boost does not do.** Coverage's judgment stays in the main thread at the session tier, so the boost only makes coverage mandatory; the coverage-loop caps that nothing applied are gone. On 8 or more cards under a `Goal:` marker task-runner reviews by range, and its closing teeth round stands in for per-card negative control, under `goal-lean` too.
- **The goal ledger's entry format is stated.** Each entry is a `- ` line or a `## ` heading, which is what `goal-ledger-check.sh` counts. A ledger kept as a table halted the run at the `Goal: true` stamp.
- **grill asks why when the request gives no reason,** in one dialog before round 1 with two to four suggested reasons and room for the user's own, instead of deriving one (`references/prompt-upgrade.md`). A question dialog that closed on the host's idle timeout answered only what was selected: the rest are ASSUMED, source `timeout`.
- **`/taskmaster:brainstorm` can end with "not building".** It asks once, records the reason and what would change the answer in `.cc-artifacts/taskmaster/no-go/`, clears its phase and offers no handoff. With the approaches plugin it now follows that plugin's own rule: an inline slate by default, the blind panel only when the idea reworks existing code.
- **Card sizes are a split test, not a label.** "Sized S/M/L/XL" had no field in a card and no column in the index. The rule now says what it did: anything bigger than one sitting is split.
- **`../verify-teeth/SKILL.md` is reachable.** task-cards' lint step points at it for the fix behind each `verify-teeth: <reason>`; the skill is in no listing and nothing named its path.
- Corrections with no change in behaviour: the README lists six hooks, all fifteen scripts and the `:redteam` and `:coverage` commands, names the red-team and coverage steps, and says the brainstorm write guard has no off switch; the `clarify-gate` and `preview-guard` lane rows describe what the hooks read; a missing `Detail:` line and an unreachable skill stamp are called warnings, not gates; `milestone-file-sets.md` reads the `<file path>` attribute; grill no longer calls specs non-scratch; `/taskmaster:task` says its handoff never adds `--tracks`.

## 0.59.0 — 2026-11-13

- **A pass is looked at in a real browser before you see it.** `scripts/preview-check.sh [--page PATH] [--widths 375,768,1280]` loads a page (default `current.html`) from the preview server, starting it when none runs, in a local headless Chromium-family browser at each width, and prints one escaped JSON object per line: findings, widths not reported, then a summary; exit 0 is clean, 1 findings, 3 to 6 not checked or not at every width.
