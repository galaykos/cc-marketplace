Why change

Today's dispatch table has no workspace_id global scope, so every read is a full-table scan and one tenant's backlog delays another's. Rows are soft-deleted rather than archived and the foreign key onto owner_id is nullable, which is why retries fan out.

How it works

  1. Mint a token: POST /api/v1/tokens with an api key.
  2. Enqueue: POST /api/v1/tasks/{queue} with the payload.
  3. Poll GET /api/v1/tasks/:id or take the webhook payload.

Limits, and what this is not

  • Rate limit: 600 requests per minute per workspace; over it you get 429.
  • A revoked token returns 403 on the next call, not at the next renewal.
  • No scheduler. Relaydeck runs what you hand it, when you hand it over.
