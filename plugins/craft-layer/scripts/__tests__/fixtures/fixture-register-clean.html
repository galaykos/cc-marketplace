Why change

Every team builds this twice. The first version is a nightly script and one table. The second is the on-call rota that grew around it: one customer's overnight import quietly delays everybody else's, the same work runs again because nobody could tell it had finished, and answering “is it stuck?” means someone opening a console at 11pm.

You did not set out to maintain a job runner. You are maintaining one.

How it works

  1. Mint a token: POST /api/v1/tokens with an api key.
  2. Enqueue: POST /api/v1/tasks/{queue} with the payload.
  3. Poll GET /api/v1/tasks/:id or take the webhook payload.

Calls carry a Sanctum bearer token minted per workspace; a consumer holding ability:machine may enqueue and nothing else can.

Limits, and what this is not

  • Rate limit: 600 requests per minute per workspace; over it you get 429.
  • A revoked token returns 403 on the next call, not at the next renewal.
  • Every read is scoped by workspace_id, so a shared queue across two of your own tenants needs two workspaces.
  • No scheduler. Relaydeck runs what you hand it, when you hand it over.
